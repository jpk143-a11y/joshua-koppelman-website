# Project notes

Edit copy in `content/site.json`, layouts in `src/app.js`, and design in `src/styles.css`. Add assets to `public/assets/` and map placeholder keys through `photoSources`. Do not edit generated `dist/` or `docs/` files directly.

Run `npm run check` and `npm run build`. Include the regenerated `docs/` files in the same pull request; GitHub Pages publishes `main` / `docs` once enabled in repository settings. Keep the site dependency-free and pre-render every page so visitors can read it without JavaScript.

Use branches and pull requests. Merging `main` updates the connected Vercel production project. Preserve existing deployment projects and URLs. For edits to the separately hosted Sites mirror, reuse its saved identity and native workflow rather than creating another mirror.

Keep placeholders clearly marked. Use supplied or verified facts and images. Do not invent experiences or create fake portraits. Keep the old resume and phone number unpublished. Browser draft edits are local previews, not a publishing system.
